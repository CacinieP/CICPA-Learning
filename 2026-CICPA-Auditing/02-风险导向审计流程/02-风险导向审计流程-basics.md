# 风险导向审计流程 —— 第一性原理教程

## 一、审计计划

### 1.1 初步业务活动

**目的：** 确定是否接受或保持客户关系和审计业务。

**内容包括：**
- 针对保持客户关系和具体审计业务实施质量控制程序
- 评价遵守职业道德规范的情况（独立性等）
- 就审计业务约定条款达成一致意见，签订审计业务约定书

**审计业务约定书**的核心内容：审计范围、双方责任、审计报告形式等。

### 1.2 总体审计策略和具体审计计划

**总体审计策略：** 确定审计的范围、时间和方向，指导制定具体审计计划。

**具体审计计划：** 包括风险评估程序、进一步审计程序的性质时间和范围、其他审计程序。

### 1.3 重要性

**重要性的定义：** 如果合理预期错报单独或汇总起来可能影响财务报表使用者作出的经济决策，则通常认为是重大的。

```
重要性水平 = 基准 × 经验百分比

常用基准：
  - 盈利企业：经常性业务的税前利润（5%）
  - 微利/亏损企业：营业收入或总资产（0.5%~1%）
```

**实际执行的重要性** = 整体重要性 × 50%~75%（通常）

**重要作用：**
- 决定风险评估程序的范围
- 识别和评估重大错报风险
- 确定进一步审计程序的性质、时间和范围

## 二、风险评估

### 2.1 风险识别和评估概述

**基本理念：** 风险评估是审计的起点，所有审计活动都应围绕评估出的重大错报风险展开。

### 2.2 风险评估程序

| 程序 | 说明 |
|------|------|
| 询问管理层和内部其他人员 | 了解被审计单位的经营、内部控制等 |
| 分析程序 | 识别异常或意外变动 |
| 观察和检查 | 观察经营活动、检查文件和记录 |
| 项目组内部讨论 | 分享见解、确定风险领域 |

### 2.3 了解被审计单位及其环境

**了解的方面：**
1. 行业状况、法律环境和监管环境
2. 被审计单位的性质
3. 被审计单位的目标和战略
4. 被审计单位的财务业绩的衡量和评价

### 2.4 了解内部控制

**内部控制五要素：**
1. **控制环境**：治理层和管理层的态度和措施
2. **风险评估过程**：识别和应对经营风险
3. **信息系统与沟通**：与财务报告相关的信息系统
4. **控制活动**：有助于管理层指令执行的政策和程序
5. **监控**：评价内部控制运行质量的过程

**注册会计师了解内控的目的：** 评估控制风险，决定是否信赖内部控制，设计进一步审计程序。

### 2.5 识别和评估重大错报风险

**两个层次的评估：**

| 层次 | 特点 | 应对方式 |
|------|------|----------|
| 财务报表层次 | 与整体相关，影响多项认定 | 总体应对措施 |
| 认定层次 | 与特定交易/账户/披露相关 | 进一步审计程序 |

**需要特别考虑的重大错报风险：**
- 舞弊风险
- 近期经济环境变化
- 复杂交易
- 关联方交易
- 会计计量不确定性

## 三、风险应对

### 3.1 总体应对措施

针对**财务报表层次**重大错报风险：
- 强调项目组成员保持职业怀疑
- 分派更有经验的成员
- 提供更多督导
- 在选择进一步审计程序时注意不可预见性
- 修改拟实施审计程序的性质、时间安排或范围

### 3.2 进一步审计程序

**设计考虑因素：**
- 风险的重要性
- 重大错报发生的可能性
- 涉及的各类交易/账户余额/披露的特征
- 被审计单位采用的特定控制的性质
- 注册会计师是否拟获取内控有效的证据

### 3.3 控制测试

**目的：** 测试内部控制运行的有效性。

**含义：** 控制是否按设计运行 + 执行控制的人是否具有必要权限和能力。

**何时需要控制测试：**
- 评估认定层次重大错报风险时预期内控运行有效
- 仅实施实质性程序不足以提供充分适当证据

### 3.4 实质性程序

**目的：** 发现认定层次的重大错报。

**类型：**
- **细节测试**：对交易、账户余额和披露的具体细节进行测试
- **实质性分析程序**：通过分析数据关系识别异常

**时间安排：**
- 期中实施 → 需要获取剩余期间的证据
- 资产负债表日后实施 → 可以覆盖整个期间

## 四、信息技术对审计的影响

### 4.1 IT对财务报告和内控的影响

- 减少人为错误的风险，但增加系统错误的风险
- 改变内部控制的形式和内容
- 影响审计证据的获取方式

### 4.2 IT控制

| 控制类型 | 说明 |
|----------|------|
| **一般控制** | 适用于所有IT系统的控制（如权限管理、备份、变更管理） |
| **信息处理控制** | 针对特定应用系统的控制（如输入校验、处理逻辑） |
| **公司层面控制** | 整体IT治理和战略层面的控制 |

### 4.3 CAAT和数据分析

**计算机辅助审计技术（CAAT）：**
- 利用计算机进行审计程序
- 可用于控制测试和实质性程序

**数据分析：** 通过分析大量数据识别异常和风险。

---

## 考试要点总结

1. **重要性**：影响整个审计的方向和范围
2. **风险评估**：审计的起点，所有程序围绕评估出的风险展开
3. **风险应对**：财务报表层次→总体应对；认定层次→进一步审计程序
4. **控制测试**：选择执行；实质性程序：必须执行
5. **IT审计**：一般控制+信息处理控制
