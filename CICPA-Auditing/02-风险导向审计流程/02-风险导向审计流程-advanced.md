# 风险导向审计流程 —— 综合实战

## 一、综合题解题框架

### 风险导向审计综合题标准解题步骤

**第一步：了解被审计单位及其环境**
- 行业状况与经营特点
- 目标战略与经营风险
- 财务业绩衡量与评价

**第二步：了解内部控制**
- 控制环境评价
- 风险评估过程
- 信息系统与沟通
- 控制活动识别
- 监控评价

**第三步：识别和评估重大错报风险**
- 财务报表层次风险
- 认定层次风险（固有风险 + 控制风险）

**第四步：制定风险应对措施**
- 总体应对措施（财务报表层次）
- 具体应对措施（认定层次）

**第五步：设计和实施进一步审计程序**
- 控制测试（如需要）
- 实质性程序

## 二、跨章联动图谱

### 本章与其他章节的关联考点

> 🔗 **跨科联动：风险导向审计(02) ↔ 会计各类资产的会计处理**

**风险导向审计是"以风险为导向"的系统性方法：**

| 风险评估内容 | 联动会计知识 |
|------------|-------------|
| 营业收入的风险评估 | 收入确认的五步法模型（识别合同、识别履约义务、确定交易价格、分摊交易价格、确认收入） |
| 存货的风险评估 | 存货成本计算方法（先进先出、加权平均）、存货跌价准备计提 |
| 固定资产的风险评估 | 折旧方法、减值迹象判断、资产弃置义务 |
| 应收账款的风险评估 | 坏账准备计提方法（预期信用损失法）、账龄分析 |
| 金融工具的风险评估 | 公允价值计量、套期会计 |

**实务逻辑：** 风险评估的结论直接影响实质性程序的性质、时间和范围，而实质性程序的设计需要结合具体科目的会计处理特点。

## 三、陷阱与反套路

### 3.1 重要性判断的常见陷阱

**陷阱一：选择不恰当的基准**

| 企业情况 | 错误选择 | 正确选择 |
|---------|---------|---------|
| 微利企业 | 税前利润（金额小，可能为负） | 营业收入 |
| 周期性波动企业 | 本期税前利润（波动大） | 多年平均或营业收入 |
| 新设企业 | 税前利润（尚未盈利） | 营业收入或总资产 |

**反套路技巧：** 重要性基准应反映企业的"常态"，不应用"异常"数据。

---

**陷阱二：混淆"财务报表整体重要性"与"认定层次重要性"**

| 概念 | 定义 | 用途 |
|-----|------|------|
| 财务报表整体重要性 | 财务报表整体的重要性水平 | 计划审计工作、评价错报影响 |
| 认定层次重要性（可容忍错报） | 认定层次的重要性水平 | 指导细节测试样本量设计 |

**反套路技巧：** 认定层次重要性通常低于财务报表整体重要性（约为50%-75%）。

---

### 3.2 内部控制评价的常见陷阱

**陷阱：混淆"了解内部控制"与"测试内部控制"**

| 环节 | 目的 | 性质 |
|-----|------|------|
| 了解内部控制 | 评价内部控制的设计是否合理 | 风险评估程序 |
| 测试内部控制 | 验证内部控制是否实际运行 | 风险应对程序 |

**关键区别：**
- 了解 ≠ 测试：了解是评价设计有效性，测试是验证运行有效性
- 可以不测试，但不能不了解
- 即使不打算信赖内部控制，也需要了解（用于确定实质性程序的性质）

**反套路技巧：** "了解"是所有业务都必须执行的；"测试"是选择执行的。

---

### 3.3 风险评估的常见陷阱

**陷阱：将"风险识别"等同于"风险评估"**

| 步骤 | 内容 | 输出 |
|-----|------|------|
| 风险识别 | 识别可能被审计单位面临的风险 | 风险清单 |
| 风险评估 | 评估已识别风险的重大程度 | 重大错报风险的水平和类别 |

**反套路技巧：** 先识别，后评估。评估要考虑"可能性"和"影响程度"两个维度。

## 四、真题变式推演

### 变式一：重要性与风险评估综合应用

**情境：**
ABC会计师事务所承接B公司2025年度财务报表审计。B公司为一家中型制造企业，2025年度未经审计的财务报表数据如下：
- 营业收入：2亿元
- 税前利润：500万元
- 资产总额：1.5亿元
- 净利润：400万元

**背景信息：**
- B公司2025年赊销政策放宽，销售额增长30%
- 期末应收账款大幅增加
- 事务所确定的重要性基准为税前利润的5%

**问题：**
1. 计算财务报表整体重要性和实际执行的重要性
2. 识别需要特别关注的重大错报风险领域
3. 假设评估认定层次重大错报风险为高水平，确定可接受的检查风险水平

**参考答案：**

**问题1：重要性计算**
```
财务报表整体重要性 = 500万元 × 5% = 25万元

实际执行的重要性 = 25万元 × 50%~75%
                 = 12.5万元 ~ 18.75万元
                 取中间值：25万元 × 75% = 18.75万元
```

**问题2：风险识别**
| 风险领域 | 风险描述 | 重大程度 | 涉及认定 |
|---------|---------|---------|---------|
| 收入确认 | 赊销政策放宽，可能存在放松信用标准 | 高 | 发生、准确性、计价 |
| 应收账款 | 余额大幅增加，可能存在回收风险 | 高 | 存在、计价 |
| 坏账准备 | 可能低估坏账准备 | 中 | 计价 |
| 存货 | 销售增长可能带来存货积压 | 中 | 存在、计价 |

**问题3：检查风险计算**
```
可接受检查风险 = 5% / 高水平重大错报风险（假设80%）= 6.25%
```

**审计启示：** 检查风险较低（6.25%），意味着需要实施更多实质性程序。

### 变式二：内部控制评价与风险应对

**情境：**
C公司为一家大型零售企业，在业务循环中存在以下内部控制：
- 销售系统自动生成销售订单
- 仓库根据已审批的销售订单发货
- 财务部门根据发货单据确认收入
- 月末由独立于销售和仓库的人员进行账龄分析

**问题：**
1. 评价上述内部控制的合理性
2. 假设注册会计师拟信赖该内部控制，应实施什么程序？
3. 如测试发现仓库发货存在未附销售订单的情况，应如何应对？

**参考答案：**

**问题1：内控评价**

| 控制点 | 控制描述 | 评价 |
|-------|---------|------|
| 销售订单生成 | 系统自动生成 | ✓ 合理（减少人为错误） |
| 发货审批 | 需附已审批销售订单 | ✓ 合理（职责分离） |
| 收入确认 | 根据发货单确认 | ✓ 合理（证据支撑） |
| 账龄分析 | 月末独立人员执行 | ✓ 合理（职责分离） |

整体评价：内部控制设计合理，职责分离得当。

**问题2：控制测试程序**
- **询问**：向相关人员询问控制执行情况
- **观察**：观察仓库发货流程
- **检查**：检查销售订单和发货单据的对应关系
- **重新执行**：独立执行账龄分析程序

**问题3：发现偏差的应对**
```
发现：仓库存在未附销售订单的发货情况

评价：
- 若样本偏差率 ≤ 可容忍偏差率 → 可以信赖，但扩大实质性程序
- 若样本偏差率 > 可容忍偏差率 → 不能信赖该控制

应对措施：
1. 扩大针对收入的实质性程序
2. 增加对期末应收账款的函证比例
3. 实施更多截止测试
4. 增加审计证据的获取
```

### 变式三：IT环境下的风险评估与应对

**情境：**
D公司为一家电商企业，业务全部通过信息系统完成。主要系统包括：
- ERP系统（财务核算）
- 订单管理系统
- 支付系统（第三方支付平台集成）

**问题：**
1. 说明IT环境对内部控制的影响
2. 注册会计师应了解哪些IT一般控制？
3. 假设订单系统存在控制缺陷，可能影响哪些认定？

**参考答案：**

**问题1：IT环境对内部控制的影响**

| 影响维度 | 具体表现 |
|---------|---------|
| 控制形式变化 | 人工控制转变为程序化控制 |
| 错误类型变化 | 人为错误减少，系统错误增加 |
| 职责分离变化 | 可能需要重新设计职责分离机制 |
| 审计证据形式 | 电子证据取代纸质证据 |

**问题2：IT一般控制**

| 控制类型 | 内容 |
|---------|------|
| 访问控制 | 系统权限管理、密码策略、特权用户管理 |
| 变更管理 | 系统变更的申请、审批、测试和上线 |
| 系统开发 | 新系统开发的项目管理、质量控制 |
| 运行管理 | 批处理作业管理、数据备份、灾难恢复 |
| 接口控制 | 系统间数据传输的完整性和准确性 |

**问题3：订单系统缺陷的影响**

| 认定 | 影响 | 原因 |
|-----|------|------|
| 收入发生 | 高风险 | 未授权订单可能虚假确认收入 |
| 收入完整性 | 中风险 | 订单遗漏导致少计收入 |
| 应收账款存在 | 高风险 | 虚假订单虚增应收账款 |
| 收入准确性 | 中风险 | 金额计算错误可能被系统放大 |

**应对措施：**
1. 更多依赖实质性程序而非控制测试
2. 实施更多截止测试
3. 增加函证比例
4. 考虑利用计算机辅助审计技术（CAAT）进行数据测试

## 五、实务衔接

### 风险评估在实务中的难点

**难点一：如何获取充分的风险评估信息？**

实务建议：
1. 充分利用项目组讨论（brainstorming）
2. 询问不同层级的人员（从管理层到基层）
3. 结合行业研究报告和监管信息
4. 关注被审计单位的历史数据和行业对比

**难点二：如何识别管理层舞弊导致的重大错报风险？**

高风险信号：
- 管理层承受业绩压力（如融资协议条款）
- 异常频繁的会计政策变更
- 临近期末的重大交易
- 非理性或复杂的关联方交易
- 内部控制存在的明显缺陷

**难点三：如何评估信息系统的复杂性？**

评估维度：
- 系统的集成度（各系统是否互联）
- 系统的定制化程度（标准vs定制）
- 数据迁移和接口的复杂性
- 关键系统的变更频率

## 六、速记总结

### 重要性确定速记

> "盈利看利润5%，微利看收0.5%~1%，实际执行是整体的五到七五"

### 风险评估程序速记

> "问看查加讨论，五步了解被审计"

### 内控五要素速记

> "环评风信沟，监在内控全"

### 风险应对速记

> "报表层次用总体，认定层次用具体；重大越高查越低，信赖过度要警惕"
